# ГдеЧУМА

Русскоязычный информационный сайт с элементами юмора: карта места, упомянутого в новостях, подборка источников и справка о чуме. Метки **не подтверждают заражение или опасность территории**.

Vue 3, TypeScript, Vite и Leaflet. Статическая сборка, без сервера, базы данных и API-ключей.

## Локальный запуск

Нужен Node.js 22.12+ (рекомендуется актуальная версия Node 22).

```sh
npm ci
npm run dev
```

Открыть адрес из терминала. В Windows PowerShell, если выполнение `npm.ps1` запрещено, использовать `npm.cmd` вместо `npm`; менять системную политику исполнения не требуется.

```sh
npm run typecheck
npm run build
npm run preview
```

Production-файлы появляются в `dist/`. Карта требует доступа к серверу тайлов OpenStreetMap; при ошибке сайт сохраняет карточку места и показывает кнопку повторной загрузки.

## Как добавить точку

Все записи находятся в `src/data/content.ts`. Добавить объект в массив `points`:

```ts
{
  id: 'another-place', // Уникальный идентификатор
  name: 'Название места',
  address: 'Город, улица, дом',
  latitude: 52.275346, // Заменить на проверенную широту места
  longitude: 104.321407, // Заменить на проверенную долготу места
  description: 'Что сообщает конкретный источник и какие сведения подтверждены.',
  checkedAt: '2026-10-03', // Дата реальной проверки, YYYY-MM-DD
  sources: [
    { label: 'Название источника', url: 'https://example.org/material' },
  ],
},
```

Координаты первой точки взяты из ссылки «Маршрут» [карточки 2ГИС](https://2gis.ru/irkutsk/firm/1548640652905815): **52.275346, 104.321407**. Убедиться, что координаты относятся именно к адресу. Широта и долгота — отдельные поля, порядок Leaflet: широта, долгота. При нескольких точках появляется переключатель карточек; карта создаёт метки из массива автоматически.

Название и описание — обычный текст, не HTML. Не добавлять персональные данные, обвинения, неподтверждённые диагнозы или метки с обещаниями безопасности. Метки остаются адресами публикаций, а не эпидемиологическими статусами.

## Как обновить подборку

Добавить объект в массив `news` того же файла:

```ts
{
  id: 'new-publication',
  title: 'Нейтральный заголовок',
  description: 'Короткий собственный пересказ с указанием источника и степени подтверждения.',
  publishedAt: '2026-10-03', // Дата публикации источника, YYYY-MM-DD
  source: 'Название издания',
  url: 'https://example.org/material',
  category: 'Сообщение СМИ', // Или 'Исследования', 'Справка'
},
```

Обновить `site.updatedAt` на дату фактической проверки подборки. Записи сортируются по дате публикации, новые выше. Не менять старые даты на сегодняшние ради видимости свежести. Автоматического парсинга и обновления нет.

После редактирования выполнить проверку типов и сборку, затем отправить коммит в `master`. GitHub Actions пересоберёт сайт. Добавление записей возможно и через редактор файла на GitHub.

URL тайлов, атрибуция, начальный центр и масштаб карты находятся в `site.map`. Для большей нагрузки можно заменить поставщика тайлов, сохранив его атрибуцию. Не включать массовую загрузку, офлайн-кэширование или предзагрузку карт; соблюдать [политику OSM](https://operations.osmfoundation.org/policies/tiles/). Запросы браузера должны сохранять HTTP Referer; не устанавливать `Referrer-Policy: no-referrer`.

## Публикация на GitHub Pages

Репозиторий: https://github.com/Madridka/gdeChuma. Основная ветка: `master`. Workflow: `.github/workflows/deploy.yml`.

1. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
2. Убедиться, что GitHub Actions разрешён в **Settings → Actions → General**, а environment `github-pages` допускает публикацию из `master`.
3. Отправить код в `master` или выбрать **Actions → Check and deploy to GitHub Pages → Run workflow → master**.
4. Дождаться успешных задач **Typecheck and build** и **Deploy**. Ошибка сборки предотвращает публикацию новой версии. Для pull request выполняются только установка, проверка типов и сборка.

Workflow использует `npm ci` и lockfile; секреты, персональные токены и сторонний хостинг ему не нужны. `GITHUB_TOKEN` автоматически предоставляется GitHub, для публикации используются разрешения Pages и OIDC.

### Домен gdechuma.ru

Домен должен быть зарегистрирован на владельца, нужен доступ к DNS. До настройки DNS публикация сборки не означает, что домен работает.

1. Рекомендуется подтвердить владение доменом в **настройках аккаунта → Pages → Add a domain**. GitHub покажет TXT-запись `_github-pages-challenge-Madridka.gdechuma.ru`; скопировать **точное значение, выданное GitHub**, в DNS и подтвердить проверку. Не использовать выдуманное значение TXT.
2. В репозитории **Settings → Pages → Custom domain** указать `gdechuma.ru` и сохранить. Файл `public/CNAME` включается в сборку, но при публикации через Actions не заменяет настройку Custom domain.
3. У DNS-провайдера создать четыре A-записи для корня (`@`):

   | Тип   | Имя | Значение           |
   | ----- | --- | ------------------ |
   | A     | @   | 185.199.108.153    |
   | A     | @   | 185.199.109.153    |
   | A     | @   | 185.199.110.153    |
   | A     | @   | 185.199.111.153    |
   | CNAME | www | Madridka.github.io |

   `www` — необязательный дополнительный адрес. Не менять почтовые MX/TXT и прочие независимые записи. У корня не должно оставаться конфликтующих A/AAAA или CNAME от прежнего хостинга. При наличии CAA убедиться, что разрешена выдача сертификата GitHub Pages согласно документации.

4. Дождаться проверки DNS и выпуска сертификата в Settings → Pages, затем включить **Enforce HTTPS**. Распространение DNS может занять до 24 часов.
5. Проверить `https://gdechuma.ru/`, favicon, JS/CSS, карту и внешние ссылки. Убедиться, что браузер не показывает ошибку сертификата. Если настроен `www`, проверить перенаправление на основной домен.

Актуальные значения и правила: [GitHub — настройка домена](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site), [подтверждение владения](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages).

`base: '/'`, canonical и метаданные рассчитаны на `gdechuma.ru`. Адрес вида `Madridka.github.io/gdeChuma/` до подключения домена не является целевым: для временного запуска в подпапке понадобится изменить Vite base, пути метаданных и настройку домена.

## Проверка перед публикацией

- `npm run typecheck` и `npm run build` проходят.
- Первоначально одна метка; её карточка показывает адрес, дату, источники и ограничение смысла метки.
- Нажатие метки, масштабирование, перемещение и «К Иркутску» работают.
- Вторая запись в `points` отображается автоматически и доступна в переключателе.
- При блокировке `tile.openstreetmap.org` доступны текстовая карточка и повтор загрузки; после восстановления сети карта загружается.
- На телефоне и при увеличении текста нет горизонтальной прокрутки, источники и атрибуция не перекрыты.
- Навигация, ссылки, метки и «Вова?» доступны с клавиатуры. Пасхалка не воспроизводит музыку автоматически.
- Подключение домена завершено только после проверки успешного Actions и HTTPS на самом домене.
